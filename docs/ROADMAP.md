# Этапы разработки

Этапы завершаются проверяемыми результатами. Сроки оцениваются разработчиком после проверки API и согласования темы; текущий комплект не задаёт выдуманный календарь реализации.

| Этап | Результат | Условие перехода |
| --- | --- | --- |
| E0 Совместимость | Изолированный OpenCode профиль, текущая OpenAPI, MAX capabilities, выбор версий, карта FR/NFR | Настоящий текст через OpenCode; безопасный probe MAX при наличии доступа; документированы недоступные функции |
| E1 Основа | Конфигурации, база, миграции, источники, scheduler, inbox, audit | AC01, AC03, AC04, AC06 и базовая авторизация |
| E2 Редакционный цикл | Повторы, события, перевод, OpenCode задания, черновики и проверки | AC07–AC11 на эталонной выборке, offline E2E |
| E3 MAX | Подключение, права, календарь, outbox, отправка, unknown и исправления | AC02, AC05, AC12–AC15 и live пост в тестовом канале |
| E4 Эксплуатация | Бюджеты, наблюдение, копии, установка и перенос | AC19–AC23, восстановление на другой машине |
| E5 Развитие канала | Отчёты, планы, медиакит, коммерческий календарь | AC16–AC18, режим plan_only без нежелательных внешних действий |
| E6 Расширения | Несколько действующих каналов, MTProto, медиа, платёжные и рекламные адаптеры | Отдельная capability приёмка и бюджет для каждого расширения |

## Первая версия

Рабочая первая версия включает E0–E5. На E3 можно провести ограниченный пилот, но нельзя считать продукт полностью принятым без переносимости и эксплуатационной проверки. Документы и тесты обновляются на каждом этапе вместе с кодом.

## Независимые работы

Неопределённая тема и отсутствующий токен не мешают E1, fake коннекторам, offline редакционным сценариям и portable сборке. Настройка аккаунта MAX и публичного webhook нужна для соответствующих live возможностей. Это явные зависимости, а не основание остановить всю разработку.

## Готовность задачи разработчика

Каждая задача ссылается на FR или NFR, указывает вход, ожидаемое изменение, тест и миграции. Завершение задачи означает код и затронутые проверки, а не только описание подхода. Если выбран другой стек или способ интеграции, оформить ADR в журнале решений и сохранить все требования приёмки.
