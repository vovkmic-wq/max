# Запуск агента нейровидео

В проекте реализован агент версии 0.1.0: FastAPI панель, постоянная очередь и история, OpenCode адаптер, RSS/HTML и webhook сбор, редакционные проверки, перевод через OpenCode, календарь, сервис отправки MAX, импорт коротких MP4 и шифрованное резервирование. Тема в TOPIC.md — короткие видео, созданные нейросетями, продолжительностью до 60 секунд.

Локальные проверки выполняются с SQLite и фикстурами внешних сервисов. PostgreSQL поддержан SQLAlchemy моделями и серверным профилем Compose; работа с настоящим PostgreSQL в этой установке не принята. Генератор видео не подключён: приложение принимает готовые ролики и проверяет их формат, длительность и права. Фикстурные ролики не обозначаются как результат нейросети.

## Быстрый запуск Windows

Из корня проекта:

```powershell
.\scripts\install.ps1
.\scripts\start.ps1
```

На этой машине зависимости уже установлены в `.venv`, а OpenCode 2.0.17 — в локальном `node_modules`. Панель доступна по адресу `http://127.0.0.1:8080`. В поле входа вставить значение APP_AUTH_SECRET из собственного `.env.local`. Для редактора используется APP_EDITOR_SECRET, для просмотра — APP_VIEWER_SECRET. Значения не отправлять в чат и не включать в архив.

Команда serve запускает панель и один scheduler worker. Отдельный worker одновременно с этим процессом в SQLite режиме не запускать. База — `data/state/agent.db`. База, журналы, медиа, учётные данные и демонстрации исключены из пакета исходников.

## Проверка и демонстрация

```powershell
.\.venv\Scripts\max-agent.exe doctor
.\scripts\test.ps1
.\.venv\Scripts\python.exe scripts\demo.py
```

Демонстрация создаёт отдельную установку в `data/demo`, материал и черновик с пометкой локальной фикстуры. Внешние источники и MAX не вызываются. Повторный запуск не добавляет дубли. Для просмотра демонстрации можно запустить `max-agent --root data/demo serve --port 8081`; её локальные ключи находятся в `data/demo/.env.local`.

## OpenCode

Редакционные задачи выполняются через выделенные V2 сессии с deny для всех инструментов. Для текущей версии принят контракт `POST /api/session` → `POST /api/session/{id}/generate`; по завершении сессия прерывается и удаляется. Авторизация сервера — HTTP Basic с именем opencode. Снимок актуальной схемы находится в `docs/research/opencode-runtime-openapi.json`.

Запуск отдельного runtime:

```powershell
.\.venv\Scripts\python.exe scripts\serve_opencode.py --binary "$PWD\node_modules\@opencode\cli\bin\opencode.exe"
```

Скрипт скрывает вывод runtime и сохраняет созданный пароль только в игнорируемом `data/opencode-runtime/access.json`. Рабочая конфигурация провайдера находится рядом в opencode.json. На другой машине её нужно создать из `config/opencode.example.json`, задав доступный адрес собственного провайдера. Старый каталог `C:\script\20260926-opencode` для запуска новой установки не требуется.

В конфигурации V2 применяются providers, package и settings. Исходный reference проект использовал provider, npm и options; эти поля не переносились в рабочий V2 профиль. Модель задаётся OPENCODE_MODEL_ID либо model_id в app.json. Настоящий доступ к модели проверяется запросом генерации, отдельно от ответа API сервера.

Текущий локальный профиль обращается к существующей proxmox/qwen35-4b. Проверка сессии прошла, запрос к провайдеру вернул 503, а каталог модели не был доступен. Приложение сохраняет такие задания как failed/retry_wait; успешная генерация не заявлена. Для платной модели требуется max_task_cost_rub и ненулевой daily_llm_limit; неизвестная цена блокирует вызов. Пока V2 не отдаёт стоимость, платная reservation сохраняется.

## Источники и публикация

Заполнить `config/sources.json` реальными источниками, подтвердить права, доступ и связь с main. Шаблонные источники отключены. Для HTML создать профиль CSS селекторов в `config/extraction`. Telegram получает разрешённые channel_post события через webhook; MAX чтение требует прав администратора. Самостоятельный MTProto сбор пока не реализован.

Для MAX задать MAX_BOT_TOKEN локально, переключить max.adapter_mode на live, создать канал через владельца и добавить бота. В панели подключить chat_id, проверить права, затем выбрать режим review или autopublish в TOPIC.md и применить новую конфигурацию. Начальный режим dry_run предотвращает отправку. Пауза дополнительно блокирует новые публикационные запросы.

Для готового видео поместить MP4 внутрь проекта, например в `data/incoming/clip.mp4`, и передать владельцем:

```text
POST /api/v1/drafts/{id}/video
{"path":"data/incoming/clip.mp4","rights_basis":"Собственный ролик с правом публикации"}
```

Импорт проверяет файл через FFmpeg, размер и длительность, сохраняет копию по SHA256, создаёт новую ревизию и отзывает одобрение. Дальше редактор одобряет точную ревизию. Перед отправкой хеш проверяется вновь. Видео загружается через официальный MAX upload API; потерянный результат отправки остаётся unknown до сверки. HTTP адаптер генератора видео пока является отключённой точкой расширения.

## Резервирование и перенос

Остановить worker и поставить каналы на паузу. Задать MAX_AGENT_BACKUP_KEY — ключ формата Fernet из собственного защищённого хранилища. Команды:

```powershell
.\.venv\Scripts\max-agent.exe backup C:\backups\max-agent.enc
.\.venv\Scripts\max-agent.exe --root C:\new-agent restore C:\backups\max-agent.enc
```

На новой машине сначала установить исходники и настройки, но не запускать serve или doctor до restore: они создают активную запись конфигурации. Restore разрешён только в пустую базу, проверяет шифрование и хеши, переносит материалы, черновики, историю, очередь, конфигурации и медиа. Каналы после восстановления остаются на паузе. Секреты переносить отдельно. Старый publisher должен быть остановлен.

## Границы версии

Автозакупка рекламы, платежи, платный доступ, генерация видео, распознавание аудио, полноценная обработка источников с альбомами и production приёмка относятся к дальнейшим этапам. План продвижения, оформление, учёт ручных метрик и коммерческий контроль доступны в сервисе. Семантические кластеры и перевод используют OpenCode; их точность на реальном тематическом наборе ещё требует приёмки.
