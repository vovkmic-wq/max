# Гибридный канал нейровидео

Версия 0.2.0 реализует два потока: разрешённые ролики из источников и собственные видеопроекты. Оба потока заканчиваются черновиком и одобрением редактора. Загрузка в MAX выполняется существующим сервисом публикации с календарём, паузой и сверкой неизвестного результата.

## Собственные ролики

В панели открыть «Собственный ролик». Можно поручить OpenCode подготовить сценарий по идее или вручную заполнить JSON. Сценарий содержит русский заголовок, подпись, основание использования материалов и до 12 сцен. Каждая сцена задаёт визуальный prompt, negative_prompt и длительность. Общая длительность не превышает 60 секунд.

Сценарий сохраняется в «Видеопроектах». Одобрение генерации привязано к revision и SHA256 плана. Оно разрешает создание сцен, но не публикацию. После завершения генерации worker собирает ролик, проверяет результат и создаёт review_pending черновик. Готовые собственные сцены также можно импортировать по локальному пути и собрать без вызова генератора.

Монтаж приводит сцены к одному размеру и 24 кадрам в секунду, сохраняет звук имеющихся сцен, добавляет тихую дорожку для сцен без звука и склеивает их в MP4. Новая озвучка и музыка автоматически не создаются. Начальный формат — 720 на 1280. QA проверяет декодирование всего видео, длительность, размер, чёрные кадры и зависания. Три кадровых отпечатка включают форму изображения и средний цвет; похожие ролики отправляются на ручную проверку. Это эвристика, а не доказательство смыслового тождества.

## Генератор ComfyUI

Реализован один адаптер — собственный ComfyUI сервер. ComfyUI 0.39.0 установлен в отдельном CPU контейнере Proxmox и прошёл проверку API и перезапуска службы. [Первичная установка](COMFY_PROXMOX.md). В VM 109 установлен Wan 2.1 1.3B с Vulkan runtime; одобренный workflow ComfyUI обращается к GPU этой VM, затем сохраняет MP4. Получен настоящий нейросетевой тестовый ролик. [Настройка, результаты и ограничения](WAN_VM109.md). Качество минимального профиля низкое; полноразмерное видео и публикационная пригодность требуют отдельной проверки.

На сервере генератора оператор выбирает и проверяет workflow для text-to-video с MP4 выходом, затем экспортирует его в API формате. Рабочий JSON граф помещается внутри проекта, например в data/incoming/workflow.json. Регистрация:

```powershell
.\.venv\Scripts\python.exe scripts\configure_comfy.py `
  --workflow data/incoming/workflow.json `
  --url http://127.0.0.1:8188 `
  --positive-node 6 --negative-node 7 --seed-node 3 --local-zero-cost
```

Числа — примеры идентификаторов. Указать реальные узлы своего графа. --positive-input и --seed-input задают имена полей; --frames-node и --frames-input позволяют связывать число кадров. --fps должен соответствовать генерации. Если модель требует специального числа кадров, задать совместимый параметр в workflow и не включать автоматическое frames связывание.

Скрипт проверяет структуру и привязки, сохраняет fingerprint и разрешённые классы узлов в локальный app.json. Запрос к серверу и генерация при регистрации не выполняются. После настройки перезапустить сервис. Флаг --local-zero-cost означает явное подтверждение владельцем, что workflow не обращается к платным API. Без этого подтверждения цена и лимиты должны быть заданы отдельно; стоимость из графа автоматически не определяется.

Подтверждённый workflow неизменяем для уже запущенной сцены. Модель меняет только связанные входы prompt, negative_prompt, seed и frames. Она не может добавить узел или переписать граф. Секреты не передаются в prompt.

Используются официальные [маршруты ComfyUI](https://docs.comfy.org/development/comfyui-server/comms_routes): отправка в /prompt, получение /history, сверка очереди и загрузка /view. История может возвращать MP4 под videos, gifs или images; последний вариант используется штатным [PreviewVideo](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_api/latest/_ui.py).

## Надёжность и расходы

Перед запросом сохраняется submitting и уникальный request_id. Потерянный ответ переводит сцену в submit_unknown. Worker ищет свой идентификатор в очереди и истории. Отсутствие записи не означает разрешение отправить запрос повторно. Уже сохранённые remote_id и сцены продолжают обрабатываться после перезапуска.

Для собственного бесплатного сервера явно используется local_zero_cost. Иначе требуется max_scene_cost_rub. Ограничения max_project_cost_rub и daily_generation_limit_rub проверяются до каждого запроса и включают неразрешённые reservations. Дневное окно генерации — последние 24 часа. Резервирование транзакционное; неизвестный расход сохраняется зарезервированным.

task_timeout_seconds ограничивает ожидание работающей сцены. Отмена проекта прекращает работу агента над ним. Глобальный /interrupt генератора не вызывается, поскольку он может остановить чужое задание. Уже отправленная задача может продолжаться на сервере; для её физического прерывания используется панель самого ComfyUI. Reservations при неопределённом результате сохраняются.

Сбой монтажа создаёт render_failed с кодом ошибки. Повторная сборка разрешена отдельным действием владельца. Не следует запускать второй worker одновременно с serve в SQLite профиле.

## Подборки из источников

Реестр config/sources.json поддерживает purpose: ideas, news, videos и mixed. RSS видеовложения сохраняются отдельно как material_media. В панели «Видео источников» можно подготовить черновик с русской подписью и обязательной ссылкой.

Скачивание разрешается, когда источник активен, относится к выбранному каналу, purpose допускает видео и подтверждены allow_storage, allow_media и allow_full_repost. Полная перепубликация также должна быть разрешена в TOPIC.md. Пример источника не означает выданные права; он остаётся отключённым.

URL проходит ту же защиту от доступа к локальной сети и опасных редиректов, что и статьи. Размер ограничен, MP4 декодируется и проверяется. Повтор файла с тем же SHA256 не создаёт второй черновик в канале. API других мессенджеров не предоставляет произвольного доступа к чужим видеоканалам; такие материалы можно импортировать владельцем при подтверждённых правах.

## API

| Метод | Назначение |
| --- | --- |
| POST /api/v1/videos | Создание проекта по plan или idea через OpenCode |
| GET /api/v1/videos | Проекты и хеши планов |
| GET /api/v1/videos/{id} | Сцены, remote_id, состояния и ошибки |
| POST /api/v1/videos/{id}/approve-generation | Одобрение revision и plan_hash владельцем |
| POST /api/v1/videos/{id}/import-scene | Импорт своей сцены и права |
| POST /api/v1/videos/{id}/poll | Проверка очереди и результата |
| POST /api/v1/videos/{id}/assemble | Сборка готовых сцен |
| POST /api/v1/videos/{id}/cancel | Локальная остановка проекта |
| GET /api/v1/source-media | Найденные видеовложения |
| POST /api/v1/curate | Подборка по media_id, channel_id и caption |
| GET /api/v1/assets | QA и происхождение готовых видео |
| GET /api/v1/assets/{id}/preview | Просмотр с авторизацией |

Все изменяющие видеопроизводство действия требуют роли owner. Подготовленный черновик одобряет editor или owner через прежний API. Контекст original разрешает творческую подпись без чужого первоисточника только для сервером созданного видеопроекта; произвольный ответ модели не получает это исключение.

## Перенос и проверка

Миграция 0002 добавляет проекты, сцены, активы и вложения материалов. Копии версии 0.1 с отсутствующими новыми таблицами принимаются как пустые таблицы; неизвестные таблицы отклоняются. Медиа и состояние входят в шифрованное резервирование. Workflow, конфигурацию собственного генератора и секреты переносить отдельно; при смене backend binding агент блокирует автоматическое продолжение старого запроса.

Проверены контрактные ответы ComfyUI и реальные операции FFmpeg. Проверка на установленном генераторе с настоящей видеомоделью, действующими источниками и MAX каналом требуется отдельно. Демонстрационные файлы являются техническими фикстурами и не обозначаются как нейросетевые результаты.
