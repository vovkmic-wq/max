# Пошаговый промпт для реализации изображений в MAX

Работай в проекте MAX Channel Agent. Сохраняй текущие источники, публикации и паузу каналов. Используй для оценки изображения только модель, исполняемую локально. Интернет нужен лишь для получения разрешённых файлов и их публичных метаданных. Управление из Codex должно быть необязательным: все операции доступны и обычной командной строке.

1. Проверь активную конфигурацию, состояние канала `test`, доступные локальные модели и публичные API кандидатов. Для каждого источника установи, доступны ли просмотры, рейтинг/избранное и лицензия каждого файла. Не подставляй придуманные значения при отсутствии метрик.
2. Создай реестр 30 разных бесплатных площадок: Pixabay API с локальным ключом и 29 источников через открытый Openverse API. Для каждого файла запиши автора, страницу оригинала, ссылку на конкретную лицензию и время проверки. Не используй платные API.
3. Добавь ограниченный загрузчик с проверкой домена, переадресаций, размера и формата; Openverse-файлы получай только через фиксированный прокси API. Отвергай неподтверждённые права, повреждённые и маленькие изображения. Отсутствующие показатели популярности отмечай как недоступные, не подставляй нули как реальные счётчики.
4. Добавь локальный визуальный ранжировщик, документируй версию и SHA-256 весов. Для Pixabay сначала отсекай файлы с недостаточными реальными просмотрами и рейтингом; для остальных используй локальную тематическую оценку. Удаляй повторы по ID, URL, SHA-256 и визуальному хешу. Выбирай не более 10 разных изображений.
5. Сохраняй результат и причины отбраковки. В публикацию передавай исходное изображение без добавленных плашек, инфографики, текста и обрезки; сверяй SHA‑256 файла. Автор, источник, лицензия и доступные счётчики должны находиться в подписи. Сверяй разрешение источника на использование в соцсетях. Предусмотри явное одобрение текущей ревизии перед публикацией.
6. Расширь браузерную отправку MAX до одного изображения JPG/PNG и подписи. Сохраняй outbox до клика, проверяй пост после перезагрузки, неизвестный исход не повторяй автоматически.
7. Добавь команды `images scan`, `images scan --all-sources --unused`, `images top`, `images status`, `images publish`, `images auto-run`, `images schedule status|pause|resume|tick` и `images caption`, а также инструкцию для необязательного управления из Codex. Полный обход должен показывать результат каждого источника. Встрой планировщик в процесс MAX (`serve` и `worker`) без внешней программы расписания. Он должен исключать ранее использованные файлы, выполнять не более одной попытки за четырёхчасовой интервал Москвы и сохранять остановку после ошибки до проверки оператором. Подписи содержат только сведения для читателя; служебную фразу об отсутствии плашек не добавляй. Исправления опубликованных подписей должны сохранять вложение, подтверждаться после reload и исключать повторный клик при неизвестном результате.
8. Проведи тесты прав, фильтров, модели, повторов, неизвестного исхода и публикации на изолированной HTML-фикстуре. Запусти реальный сбор и честно сообщи число подтверждённых кандидатов. Публикуй только при наличии одобренного файла, активного целевого канала и явно разрешённых владельцем условий.
