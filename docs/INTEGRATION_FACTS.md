# Проверенные сведения об OpenCode и MAX

Проверка выполнена в сессии 5 и 6 октября 2026 года. Локальные факты относятся к прочитанным файлам и выполненной команде; сведения API относятся к официальной документации на момент просмотра. До реализации live интеграций их нужно повторно проверить для принятых версий.

## Локальная среда OpenCode

В `C:\script\20260926-opencode\package.json` задана зависимость `@opencode/cli` с диапазоном `^2.0.17`. Установленный package.json и package-lock.json фиксируют 2.0.17. Команда `node_modules\.bin\opencode.cmd --version` вернула `opencode v2.0.17`.

Пакет указывает репозиторий [anomalyco/opencode](https://github.com/anomalyco/opencode), платформы Windows, Linux, macOS и архитектуры x64/arm64. Наличие пакета для платформы не является проверкой установки на ней.

В корне есть конфигурации, launcher скрипты, служебные файлы других приложений и `workspace/ozon_market_analytics`. Они не являются обязательными компонентами нового сервиса. Конфигурации с возможными секретами не включены в комплект; их значения не переносились.

## Интерфейс OpenCode

Локальный файл `opencode-openapi.tmp.json` описывает experimental HttpApi с `/api/session`, `/api/session/{sessionID}/prompt` и `/api/experimental/generate`. Это сохранённый снимок, а не проверка работающего сервера. Публичная V2 документация описывает experimental API и показывает `/api/generate`; расхождение требует проверки актуальной схемы конкретного бинарника. [Официальный V2 API](https://dev.opencode.ai/v2/docs/api/).

Для V2 документированы `permissions` как массив правил и имена `shell`, `subagent`; старые `permission`, `bash`, `task` не следует переносить. Принятая конфигурация должна проверяться тестом ограничений. [V2 permissions](https://dev.opencode.ai/v2/docs/permissions/).

Редакционный runtime проектируется с запретом инструментов по умолчанию. Если тип задания требует конкретного инструмента, он добавляется явно. Исходный общий конфиг другого проекта не используется как runtime policy. В этой сессии сервер и генерация не запускались; подтверждена только версия CLI.

## MAX

| Подтверждённое сведение | Следствие для проекта | Основание |
| --- | --- | --- |
| Текущий base URL в документации — platform-api2.max.ru; токен передаётся в Authorization | Настраиваемый адрес и отсутствие токена в query | [Обзор API](https://dev.max.ru/docs-api) |
| GET /chats больше не поддерживается с июня 2026 | Хранить реестр chat_id из событий и подключения владельцем | [Список каналов](https://dev.max.ru/docs-api/methods/GET/chats) |
| POST /messages отправляет посты; текст до 4000 символов, до 2 сообщений в секунду на канал | Проверка итоговой длины и ограничитель; проектный предел ниже API | [Отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages) |
| GET /messages по chat_id требует администратора | Источник MAX сначала подтверждает права | [Чтение сообщений](https://dev.max.ru/docs-api/methods/GET/messages) |
| Production события используют webhook HTTPS на 443 с доверенным сертификатом; secret передаётся в X-Max-Bot-Api-Secret | Публичный ingress и проверка подлинности до записи inbox | [Подписка](https://dev.max.ru/docs-api/methods/POST/subscriptions) |
| Long Polling не подходит для production приёма MAX событий | Использовать его только в поддерживаемом dev сценарии | [События бота](https://dev.max.ru/docs-api/use-cases/bot-in-chats-and-channels) |
| Условия создания публичного канала зависят от аккаунта и выбранного способа | Проверка условий владельцем во время подключения | [Каналы](https://dev.max.ru/help/channels) |

В просмотренном [публичном перечне API](https://dev.max.ru/docs-api) нет метода создания канала. Это основание проектного решения create_channel=unsupported в первой версии, а не утверждение о невозможности любых будущих или партнёрских интерфейсов. Агент готовит оформление; владелец создаёт канал поддерживаемым способом. Новый официальный интерфейс можно принять отдельным тестом.

События подтверждаются после постоянной записи. Если подписка потеряна, необходимо проверить и восстановить её, а не предполагать бесконечное хранение событий. TLS верификация не отключается; необходимые сертификаты устанавливаются процедурой доверия владельца.

## Telegram и другие источники

Бот получает сообщения каналов, в которых он присутствует; это не даёт произвольного доступа к любому указанному каналу. [Telegram Bots FAQ](https://core.telegram.org/bots/faq). Для отдельного клиентского API нужны собственные api_id, api_hash и пользовательская авторизация. [Создание Telegram приложения](https://core.telegram.org/api/obtaining_api_id).

Для других мессенджеров пока не выбран конкретный API. Поддержка означает возможность добавить адаптер после проверки, а не уже реализованный сбор со всех платформ.

Создание настоящего текста OpenCode через нужный транспорт; совместимость модели; доступ к выбранным источникам; работа конкретного MAX токена и прав; webhook доставка; поддержка статистики и исправлений; установка на второй машине. Ни один из этих результатов не следует из документации или существования библиотеки.
