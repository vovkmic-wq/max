# Публикация в MAX через браузер

Добавлен MAX адаптер browser: он открывает отдельный профиль Chrome и отправляет текст или MP4 через обычный интерфейс web.max.ru. Токен бота для этого режима не используется. Встроенный браузер Codex остаётся отдельной сессией; проект не извлекает из него cookies, токены или пароли.

## Установка и вход

Установить дополнительные зависимости в проектную .venv:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-browser.lock
```

Нужен установленный Google Chrome. Для другого поддерживаемого браузера можно выбрать msedge; для chromium отдельно установить браузер командой python -m playwright install chromium. Реализация использует [постоянный профиль Playwright](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context).

В игнорируемом config/app.json установить max.adapter_mode=browser и заполнить max.browser:

```json
{
  "profile_dir": "data/max-browser",
  "channel": "chrome",
  "headless": true,
  "operation_timeout_seconds": 120,
  "channels": {"-12345678901234": "Название вашего тестового канала"}
}
```

Число и название — образцы. Указать точный адрес открываемого канала и его название. Публикация допускается только в явно перечисленные каналы; адрес и заголовок проверяются повторно перед нажатием «Отправить». Профиль должен находиться внутри data и вне каталога медиа. Он не входит в Git, релизные архивы или стандартную резервную копию состояния агента. При переносе на другую машину требуется новый вход.

1. В TOPIC.md выбрать review для нужного канала. dry_run сохраняет запрет отправки. Режим autopublish для браузерного адаптера отклоняется.
2. Перезапустить агент после установки и изменения режима.
3. В панели заполнить профиль канала и chat_id. В разделе «Публикация через браузер» нажать «Войти в MAX».
4. В отдельном окне Chrome войти самостоятельно по QR-коду. Пароли, SMS-коды и CAPTCHA вводит владелец. Проект не сохраняет их в своих конфигурационных файлах.
5. Нажать «Проверить браузер», затем «Проверить и подключить» канал.
6. Возобновить выбранный канал. Проверить текст, видео и основание использования материалов; одобрить текущую ревизию черновика в календарь.

Альтернативный вход из терминала:

```powershell
.venv\Scripts\python.exe -m max_channel_agent.browser_login --root . --chat-id=-12345678901234
```

Сессия сохраняется самим Chrome в отдельном профиле. Не переносить этот каталог в публичные архивы. Закрытие рабочего приложения не удаляет вход.

## Создание канала в аккаунте проекта

Команда владельца создаёт приватный канал через обычный интерфейс MAX, сохраняет его адрес и подтверждение после перезагрузки:

```powershell
& 'C:\script\20261005-Max\.venv\Scripts\python.exe' -m max_channel_agent.cli --root 'C:\script\20261005-Max' browser-create-channel --name 'Нейровидео — тест MAX' --bind
```

Для другой установки замените пути. Флаг `--bind` добавляет адрес и точное название в разрешённые адресаты `config/app.json`. После изменения настроек активируйте их в панели. Команда не возобновляет публикации и не одобряет черновики.

Журнал создания хранится в `data/browser-channels`. Повтор той же команды возвращает сохранённый результат и проверяет доступ текущего аккаунта. Если результат неизвестен, команда не нажимает «Создать» повторно. Откройте уже созданный канал в профиле проекта и сверяйте его адрес через `--recover-chat-id=-12345678901234`; эта операция проверяет точный заголовок, право писать и наличие канала после reload. При промежуточном экране MAX команда может потребовать такую сверку.

8 октября 2026 года в отдельном аккаунте проекта создан и проверен канал **«Нейровидео — тест MAX»**, `chat_id=-79860712657053`. Это новый канал; канал во встроенном браузере Codex принадлежит другому аккаунту. Доступ и создание подтверждены. 8 октября проект опубликовал текст «Привет, это новый канал!» и подтвердил его после reload; публикация видео пока не проверена.

## Отправка и подтверждение

Сохраняются существующие роли, календарь, пауза, ограничения публикаций, одобрение ревизии и SHA-256 MP4. При смене браузерного адресата или настроек адаптера старые одобрения становятся недействительными. Браузер не открывается для неподключённого канала или dry_run.

Каждая отправка получает постоянный ID intent из outbox. Браузерный worker сериализуется блокировкой отдельного профиля. Он сохраняет sending перед кликом, затем проверяет новый пост и его вложение, обновляет страницу и подтверждает наличие поста в истории. Скриншот подтверждения и журнал сохраняются в data/browser-publications. Файл для загрузки предварительно копируется в этот каталог и проверяется по одобренному SHA-256.

Если подтверждение не получено, результат unknown не разрешает повторный клик. Действие «Сверить результат» проверяет историю и сохранённый intent; отсутствие поста не служит разрешением на повторную отправку. Уже подтверждённый журнал помогает восстановить результат после сбоя между публикацией и записью в основную базу.

external_id вида browser-UUID — локальный идентификатор подтверждения, а не официальный MAX message_id. Точный permalink поста не генерируется. Сверка опирается на новые совпадения текста в видимой истории; виртуализация длинной истории, одинаковые посты и ручное удаление могут оставить результат unknown. Проект не считает один совпадающий старый текст достаточным подтверждением.

## Ограничения

В первой реализации поддерживаются текст и один MP4. Сбор источников MAX, редактирование и удаление через браузер не реализованы; для них возвращается явная ошибка. Изменение интерфейса MAX, истёкшая сессия, отсутствие доступа к каналу, занятый профиль или оставленный вручную текст требуют внимания владельца. Чужой черновик в браузере не очищается.

Playwright установлен как отдельная опция browser. Python пакеты зафиксированы в requirements-browser.lock. Авторизация и доступ к каналу проверяются через UI, без обращения к скрытым API MAX. При публикации одновременно с человеком используйте отдельный профиль проекта.

## Проверка

Проверены реальный Chrome с изолированной HTML фикстурой: ввод текста, загрузка MP4, отправка, подтверждение после reload и отсутствие второго отправления для того же intent. Дополнительно проверены роли, ограничения профиля, изменение привязки канала, неизвестный исход отправки, подмена файла, сериализация профиля и сверка outbox. [Результаты pytest](research/browser-publishing-tests.xml).

Отдельный браузерный тест воспроизводит сбой уже после успешного клика: пост остаётся в истории, результат записывается unknown, повторный вызов не отправляет его снова, а сверка подтверждает первый пост. В наборе 24 проверки браузерного режима и создания канала. Worker повторно читает одобрение, паузу, адресата и точное содержимое из базы непосредственно перед кликом; изменение текста или пауза после начала подготовки блокирует отправку. Ruff, pip check и проверка синтаксиса JavaScript пройдены. Файлы профиля и фактические локальные секреты проверены на отсутствие в изменениях Git.

Итоговый полный прогон: **166 passed, 0 failed, 0 skipped**, 73.26 секунды. Сохраняется одно предупреждение Starlette/HTTPX из прежнего набора тестов. Проверка браузерной доставки использует HTML фикстуру, а не настоящий MAX канал.

Живая сессия Chrome после QR входа сохраняется и открывает MAX. После уточнения владельца о другом аккаунте создан новый приватный канал; его адрес, точное название и поле публикации проверены после перезагрузки. Живая текстовая публикация самим проектом подтверждена: «Привет, это новый канал!», intent 6792ac0a-35b4-4dff-8bb9-2aba8235fc90. В истории после повторного открытия ровно один такой пост. После теста канал снова поставлен на паузу и возвращён в dry_run. Публикация MP4 через проект пока не проверена. Это отдельно от предыдущей отправки картинки инструментом Codex во встроенном браузере.
