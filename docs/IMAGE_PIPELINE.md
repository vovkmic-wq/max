# Изображения: бесплатный сбор и управление из Codex

В реестре `config/image_sources.json` настроено 30 разных сайтов: Pixabay напрямую и 29 площадок через бесплатный [Openverse API](https://api.openverse.org/v1/). «Топ‑10» означает десять разных изображений, а не десять сайтов. Pixabay отдаёт просмотры и лайки; Openverse их обычно не отдаёт, поэтому эти поля не выдумываются, а подбор идёт по оценке локальной модели CLIP ViT‑B/32 ONNX на CPU. Повторы удаляются по URL, SHA‑256 и визуальному хешу. В каждом четырёхчасовом интервале опрашивается Pixabay и очередная группа площадок Openverse; за сутки проходят все 29. Список с адресами находится в [IMAGE_SOURCES.md](IMAGE_SOURCES.md).

[Документация Pixabay API](https://pixabay.com/api/docs/) разрешает бесплатный ключ после входа, требует кэшировать ответы 24 часа, ограничивать автоматические запросы и скачивать используемые изображения вместо постоянного hotlink. [Официальный FAQ Pixabay](https://pixabay.com/service/faq/) прямо допускает использование изображений в социальных сетях; условия и ограничения указаны в [лицензии](https://pixabay.com/service/license-summary/). Openverse предоставляет публичные записи с лицензиями CC0, Public Domain Mark или CC BY и ссылками на страницы оригинала; каждая запись перепроверяется перед отправкой через [его API](https://api.openverse.org/v1/). API-ответы кэшируются на сутки, файлы загружаются только через фиксированный прокси Openverse с лимитом размера. Обычный сбор ограничен 20 файлами. В MAX передаётся исходное изображение без добавленных плашек, надписей и обрезки. Автор, источник, лицензия и доступные просмотры и лайки находятся в подписи. Если конкретный файл вызывает сомнение по правам третьих лиц, не публикуйте его.

Пошаговое задание для повторной реализации — [IMAGE_PIPELINE_PROMPT.md](IMAGE_PIPELINE_PROMPT.md). Модель фиксирована ревизией `b318363e9c2fe791fd691d44862bb4cd4d7accc5`, SHA‑256 весов `06e11583385faecfa7273f7cc72b603be915ab9340269482cde69a5d0f5e3350`. Балл CLIP — тематическая эвристика, а не свидетельство лицензии или качества.

## Подготовка

Из корня установленного проекта:

```powershell
& .\.venv\Scripts\python.exe -m pip install -r requirements-images.lock
& .\.venv\Scripts\python.exe scripts\install_image_model.py --root .
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . init
```

Откройте [официальную страницу Pixabay API](https://pixabay.com/api/docs/) после входа в бесплатный аккаунт. Страница показывает личный API key. Сохраните его только в игнорируемом `.env.local` проекта как `PIXABAY_API_KEY=...`. Не отправляйте ключ в чат, Git или отчёты. Для Openverse ключ не нужен. `config/image_sources.json` создаётся из заполненного примера при `init`; для существующей установки замените старый реестр новым примером. Запросы и пороги можно менять; код принимает только Pixabay API и фиксированный Openverse API.

Тестовый канал должен быть подключён к браузерному адаптеру и оставаться на паузе между однократными публикациями. Профиль `test` работает в `review`; основной канал остаётся в `dry_run`.

## Команды

```powershell
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images scan
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images scan --all-sources --unused
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images status
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images top
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images publish --rank 1 --sha256 <sha256-из-images-top>
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images reconcile --intent-id <intent-id-из-status>
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images auto-run --dry-run
& .\.venv\Scripts\python.exe -m max_channel_agent.cli --root . images auto-run
```

`scan` сохраняет отчёт, кэш API и файлы в игнорируемом `data/image-ranking`. `status` показывает состояние и причины отказа без значения ключа. `top` показывает не более десяти разных изображений с метриками и ссылками. `publish` требует готовый топ не старше суток, ранг и точный SHA‑256. Команда сверяет метаданные из обязательного 24‑часового кэша API и повторно скачанный файл, готовит исходное изображение с подписью, одобренный черновик и outbox intent, на один вызов возобновляет тестовый канал и возвращает паузу. Изменение прав на сайте внутри срока кэша может не обнаружиться; перед публикацией просмотрите страницу файла. Неопределённая отправка не повторяется автоматически: проверьте канал и журнал `data/browser-publications`, затем выполните `reconcile`.

Codex может управлять теми же командами по поручению владельца; он не нужен для работы модели. Пример: «Запусти `images scan`, покажи `images top` с метриками, ничего не публикуй». Для отправки: «Опубликуй через проект MAX изображение №1 из текущего топа после сверки прав и SHA‑256». Само наличие ключа или запуск `scan` ничего не публикуют.

`scan --all-sources --unused` выполняет разовый обход всех включённых площадок и исключает все ранее подготовленные изображения по ID, странице и SHA‑256 исходного файла. Для этого режима лимит составляет 20 загрузок Pixabay и по две на площадку Openverse (78 для текущего реестра). `source_results` в отчёте содержит состояние и счётчики каждой площадки, включая пустые результаты и ошибки. При HTTP 403/429 сбор останавливается без повторного запроса; уже собранные записи сохраняются в `accepted_before_error`, отправка из такого отчёта блокируется. Без флагов сохраняются обычная ротация и лимит 20 файлов.

## Публикация по расписанию

`images auto-run --dry-run` проверяет доступность тестового канала, собирает свежий топ и показывает выбранный файл без отправки. `images auto-run` делает то же, затем отправляет **не более одной** нового изображения с подписью в тестовый канал за четырёхчасовой интервал Москвы (00:00–04:00, 04:00–08:00 и так далее). Ранее использованные ID, страницы и SHA‑256 исключаются ещё при сборе, поэтому после исчерпания прежнего топа отбираются следующие изображения. Перед запуском проверяется состояние браузерного профиля MAX; при неизвестном исходе прежней отправки новая публикация блокируется. Для каждого интервала в игнорируемом `data/image-ranking/auto-runs` создаётся запись попытки: повторный вызов в том же интервале не отправит вторую карточку. Даже если сбор не удался, автоматический повтор в этом интервале не выполняется. Состояния `error`, `scan_not_ready`, `channel_inspection_failed` и `unresolved_publication` требуют проверки оператором.

Планировщик встроен в процесс проекта, запускаемый командами `serve` или `worker`. Он сам проверяет интервалы Москвы: 00:00, 04:00, 08:00, 12:00, 16:00 и 20:00. Внешний планировщик и Codex ему не нужны. Управление находится в панели «Автоматические изображения» и командах `images schedule status|pause|resume|tick`; после включения первая попытка приходится на следующую границу интервала. При ошибке процесс останавливает автоматические попытки до проверки оператором. [Запуск и управление автономным режимом](AUTONOMY.md). Канал `test` между публикациями остаётся на паузе. Автоматический режим выполняет поручение владельца на одобрение одного выбранного изображения за запуск.

Общий дневной предел тестового канала — 16 постов: он допускает шесть запусков расписания и отдельную явно порученную тестовую серию из десяти изображений. Само расписание по-прежнему ограничено одной отправкой за четырёхчасовой интервал. Обычно промежуток между постами составляет 120 минут; на время явно порученной серии оператор может временно снизить его до одной минуты и обязан восстановить исходное значение и паузу после серии.

Если ключ Pixabay отсутствует, сбор возвращает `needs_source_key` и пустой топ. Если подходящих неповторяющихся изображений меньше десяти, состояние `insufficient_candidates` блокирует публикацию из неполного топа. Метаданные лицензии Openverse могут устареть или содержать ошибку исходной площадки: ссылка на оригинал сохраняется в отчёте и посте для аудита.
