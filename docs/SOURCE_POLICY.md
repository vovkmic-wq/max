# Подключение и сбор материалов

Владелец задаёт определённый пул источников. Агент собирает только зарегистрированные источники и использует новые найденные адреса как предложения на добавление. Публичная доступность материала не означает разрешение на его полную перепубликацию.

## Реестр

Реестр хранится в `config/sources.json`; [sources.example.json](../config/sources.example.json) показывает формат. id источника стабилен. channel_ids связывают источник с профилями из TOPIC.md. interval_seconds определяет частоту опроса, lookback_hours ограничивает историю при первичном сборе и восстановлении.

Для каждого источника сохраняются: тип, endpoint, язык, уровень доверия, имя ссылки на секрет, разрешённый способ доступа, права хранения и переработки, профиль извлечения, лимиты, состояние capability и дата проверки. Невалидный источник не становится активным даже если enabled=true.

## Поддерживаемые способы

| Тип | Способ | Условие и ограничение |
| --- | --- | --- |
| rss | HTTP условные запросы, разбор RSS или Atom | Предпочтительный способ; GUID и canonical URL сохраняются |
| html | HTTP и профиль извлечения статьи | Согласованные условия доступа, robots правила и ограничение частоты; JS страницы требуют отдельного адаптера |
| telegram_bot | Приём событий Bot API | Только каналы, где бот имеет доступ; произвольная история чужих каналов не предполагается |
| max_bot | Чтение доступных сообщений и события | Для чтения списка постов по chat_id подтверждаются права администратора |
| telegram_mtproto | Отдельный пользовательский клиент | Расширение: подключение аккаунта владельцем, собственные api_id и api_hash, проверка доступа и защиты сессии |
| other_messenger | Собственный адаптер | Расширение после фиксации API, прав и контрактных тестов |

Официальные ограничения Telegram и MAX собраны в [INTEGRATION_FACTS.md](INTEGRATION_FACTS.md). Коннектор, не позволяющий читать выбранный канал, возвращает unavailable; ссылка на канал не считается доказательством доступа.

## Расписание и контрольные точки

Начальный interval_seconds — 1800, минимально 60 для HTTP источников; более строгий лимит площадки имеет приоритет. Планировщик использует UTC и добавляет ограниченный jitter до 10 процентов интервала. Одновременно выполняется не более одного задания на источник.

HTTP сбор сохраняет ETag и Last Modified, обрабатывает 304 без новых материалов. Курсоры мессенджеров сохраняются после commit. Событийные источники не создают искусственных poll запросов, если API работает только через webhook; interval_seconds задаёт их проверку здоровья и разрешённую сверку.

После простоя выполняется одно ограниченное catch up задание с lookback_hours и max_items_per_run. Пропущенные тики не создают сотни одинаковых задач. Если источник не предоставляет историю, потерянные события помечаются возможным gap; отчёт не заявляет полноту.

## Нормализация

Сохранять текст, заголовок, дату публикации, дату события при наличии, автора, язык, URL, сырой хеш и вложения. Удалять навигацию, рекламные вставки сайта и повторный boilerplate. Исправлять пробелы и кодировку. Query параметры удалять только по правилам конкретного домена: универсальное удаление всех параметров может объединить разные статьи. Редирект проверяется до загрузки следующего адреса.

Если дата неизвестна, сохранять null и fetched_at отдельно. Если RSS содержит анонс, полный текст загружается лишь при разрешённом full_text. Каналы назначения исключаются из пула источников по умолчанию; иначе система должна предотвращать цикл перепубликации.

## Доступ и права

rights содержит basis, attribution_required, allow_storage, allow_derivative, allow_full_repost, allow_media и verified. Активный источник должен иметь подтверждённый способ доступа. Полная перепубликация требует согласованных прав и разрешения темы. Изображения с неизвестными правами заменяются текстом или разрешённым материалом. Водяной знак не удаляется для обхода атрибуции.

Ссылка на источник сохраняется во всех публикациях. Если rights.verified=false, материал может участвовать в оценке источника, но не в автоматической публикации. Закрытые, платные и защищённые материалы собираются лишь через разрешённый интерфейс с указанными правами.

## Ошибки и пределы

401 даёт needs_auth и прекращает повторы до обновления доступа; 403 даёт forbidden без обхода прокси; 429 даёт ожидание Retry After. GET при временных сетевых ошибках повторяется ограниченно с backoff; запреты не лечатся бесконечным повтором. Начальные лимиты: 100 материалов за запуск, ответ 5 МБ, изображение 10 МБ, до 3 редиректов и 3 попыток чтения.

Не передавать Authorization и cookies на другой домен при редиректе. Защита адресов применяется и к медиа, и к ссылке, полученной из HTML. Проверка сертификатов обязательна; добавление необходимого CA выполняется по процедуре установки, без отключения TLS проверки.
