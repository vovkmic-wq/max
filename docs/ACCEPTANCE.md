# Проверки и критерии приёмки

Приёмка доказывает поведение работающего приложения. Проверка связности нынешних документов и JSON примеров не является тестированием будущего агента. Каждый отчёт содержит дату, коммит, профиль, версии, набор входных данных, результат и безопасные артефакты.

## Статусы

DOCUMENTS_READY — согласованный комплект спецификаций. OFFLINE_ACCEPTED — цепочка с fake адаптерами и реальные локальные компоненты. LIVE_ACCEPTED — проверены настоящий OpenCode runtime и публикация в тестовый MAX канал. PRODUCTION_ACCEPTED — дополнительно проверены перенос, восстановление, права, наблюдение, ограничения и рабочая конфигурация конкретной установки. Непроверенная или отключённая capability не получает live статус.

Пороговые значения AC07–AC09 являются целями проекта. Тестовая выборка и правила разметки находятся в [редакционной политике](EDITORIAL_POLICY.md). Измерять precision и recall по парам событий; публиковать TP, FP, FN и размер выборки. Не настраивать порог на скрытой приёмочной части выборки.

## Порядок проверки

1. Unit: разбор конфигураций, canonical URL, хеши, календарь, бюджет и состояния.
2. Contract: fixtures API MAX и OpenCode выбранной версии, ошибки и capabilities, строгий JSON результат.
3. Integration: PostgreSQL транзакции, leases, inbox/outbox, restart, миграции и копия.
4. E2E offline: от источника до календаря с fake внешними адаптерами.
5. Live: ограниченное чтение разрешённого источника, реальная генерация, публикация, сверка и исправление в выделенном тестовом канале.
6. Transfer: восстановление на второй поддерживаемой машине с другим путём и повторная live проверка.

Платные операции live теста имеют заранее заданный лимит. Запуск live требует выбранных аккаунтов, источников и темы; наличие документов само по себе не разрешает отправку в пользовательские каналы.

## Отчёт

Указать точное количество passed, failed и skipped, причины пропусков, commit, версии бинарников, API snapshot hashes и профиль. Приложить очищенные trace записи, внешний ID тестового поста, хеши копии, время RPO/RTO и карту FR/NFR. Статус не повышается при пропущенном обязательном сценарии. Для optional capability допустим NOT_ENABLED с объяснением.
