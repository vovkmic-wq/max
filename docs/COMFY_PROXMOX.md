# ComfyUI на Proxmox и тестовый канал MAX

ComfyUI размещается в отдельном непривилегированном контейнере Ubuntu 24.04. Установка не меняет Python окружение гипервизора и не требует остановки существующих виртуальных машин. Для текущего сервера выбран CPU режим: обнаруженная Radeon Bonaire не используется для вычислений. Модель и рабочий сценарий нейросетевого видео подключаются отдельно после выбора подходящих ресурсов.

Проверка pip check прошла, службы max-comfyui и nftables включены для автозапуска. Повторная проверка проекта MAX: 131 тест прошёл. ## Развёртывание

Установщик [install-cpu.sh](../deployment/comfy/install-cpu.sh) предназначен только для выделенного гостя Ubuntu. Он отказывается работать на гипервизоре с pveversion, создаёт пользователя comfyui, отдельное Python окружение и службу max-comfyui.service. Исходный код берётся из официального репозитория Comfy-Org/ComfyUI, release v0.39.0. Установленные версии зависимостей сохраняются в /opt/max-comfyui/requirements.installed.txt.

```bash
# Внутри выделенного гостя; по умолчанию доступ только с localhost.
bash install-cpu.sh

# Для подключения агента с другой машины: заменить адреса своими.
COMFY_BIND=0.0.0.0 COMFY_ALLOW_IPV4="192.168.1.10,192.168.1.20" bash install-cpu.sh
```

При сетевом запуске установщик задаёт nftables правила для порта 8188. Файл /etc/nftables.conf заменяется целиком, поэтому скрипт следует запускать в отдельном госте, где нет других правил firewall. Доступ к API разрешается только заданным IPv4 адресам и localhost; IPv6 доступ к этому порту отклоняется. Интернет публикация API и перенаправление порта на роутере не выполняются. Корень ComfyUI и данные находятся в /opt/max-comfyui. Сторонние custom nodes отключены.

```bash
systemctl status max-comfyui --no-pager
journalctl -u max-comfyui -n 50 --no-pager
systemctl restart max-comfyui
curl --fail http://127.0.0.1:8188/system_stats
```

Официальные инструкции: [установка](https://docs.comfy.org/installation/manual_install), [оборудование и CPU режим](https://docs.comfy.org/installation/system_requirements).

## Проверки и подключение агента

```powershell
.venv\Scripts\python.exe scripts\probe_comfy.py --url http://SERVER:8188 --exercise --output data\comfy-live-smoke.json
```

Проверка обращается к system_stats, queue и object_info. С параметром exercise она выполняет штатный граф EmptyImage → SaveImage и загружает PNG через view. Это техническое подтверждение выполнения заданий и получения файлов, а не нейросетевая генерация.

COMFYUI_BASE_URL хранится в игнорируемом файле .env.local. После изменения адреса агент требуется перезапустить. Доступный сервер без видеомодели и одобренного API workflow остаётся в состоянии needs_configuration. Регистрация рабочего workflow описана в [HYBRID.md](HYBRID.md). Не следует регистрировать технический тест как генератор нейровидео.

При DHCP адрес гостя может измениться. Для постоянной эксплуатации закрепите его на DHCP сервере и проверьте firewall после смены адреса компьютера агента. Изменение адреса или workflow требует нового одобрения задач генерации.

## Тестовый канал

В TOPIC.md добавлен отдельный профиль test с темой нейровидео и режимом dry_run. Приватный канал «Нейровидео — тест MAX» создан в аккаунте владельца. В него вручную опубликовано техническое сообщение о создании канала. Локальная карточка с chat_id и фактическим статусом хранится в data/max-test-channel.json и не публикуется в Git.

Подключение через официальный API требует токена бота и его прав администратора в созданном канале. Вход владельца в web.max.ru не предоставляет агенту токен Bot API. Без бота подключение не отмечается успешным и автоматическая отправка не включается.

Если бота ещё нет, официальный путь — [создание и модерация на платформе MAX](https://dev.max.ru/docs/chatbots/bots-create/create). Документация повторно проверена 6 октября 2026 года: требуется верифицированный профиль организации, ИП или самозанятого; после создания бот проходит модерацию, затем становится доступен токен. Наличие такого профиля у владельца пока не подтверждено.

После получения токена сохраните его локально как MAX_BOT_TOKEN; его нельзя включать в TOPIC.md, workflow, Git или архив проекта. Добавьте бота администратором тестового канала с правом публикации, переключите max.adapter_mode на live, перезапустите агент и подключите chat_id через панель. Проверка членства и права публикации должна пройти через настоящий API. Оставьте канал в dry_run до отдельной проверки отправки.
