# Агент для ведения тематических каналов MAX

Переносимый Python-проект для ведения тематических каналов MAX: сбор изображений из бесплатных источников, локальный отбор CLIP, публикация через отдельный профиль браузера, несколько каналов с разными темами и встроенное расписание. Также доступны редакционный процесс OpenCode, собственные видеосценарии и интеграция ComfyUI.

В репозитории находятся код, шаблоны настройки, тесты и инструкции. Локальные ключи, база, модели, медиа, профиль браузера и резервные копии в Git не входят. Чистая установка использует тестовые адаптеры; реальное подключение MAX и расписание настраиваются владельцем. Планировщик работает внутри `serve` / `worker` и не зависит от Codex, cron или Windows Task Scheduler.

## Быстрый запуск

Windows, Python 3.12, PowerShell из каталога проекта:

```powershell
& .\scripts\install.ps1 -Images -Browser -SkipOpenCode
& .\scripts\start.ps1
```

Linux с Python 3.12:

```sh
INSTALL_IMAGES=1 INSTALL_BROWSER=1 INSTALL_OPENCODE=0 sh scripts/install.sh
sh scripts/start.sh
```

Панель: `http://127.0.0.1:8080`. Локальный ключ владельца создаётся в `.env.local`.
Установщик скачивает закреплённую модель CLIP и проверяет её хеш; сама оценка выполняется локально.
Для текущего источника Pixabay нужен бесплатный API-ключ в `PIXABAY_API_KEY`.
Перед публикацией настройте браузерный адаптер, разрешённые адресаты и войдите в MAX по QR-коду.

## Порядок использования

1. Прочитать краткое описание и техническое задание.
2. Заполнить TOPIC.md: реальную тему, аудиторию, разрешённые и запрещённые подтемы. Выбрать источники в отдельном реестре. До заполнения оставить канал отключённым.
3. Передать разработчику промпт разработки вместе со всей папкой. Начать с проверки совместимости OpenCode и MAX.
4. Принять локальную цепочку без публикации, затем публикацию в отдельном тестовом канале, затем перенос на вторую машину.
5. Включать автоматическую публикацию для конкретного канала после его настройки и приёмки; продвижение с расходами имеет отдельный бюджет.

Существующий проект `C:\script\20260926-opencode` служит исходной средой OpenCode и читается как reference. Новый сервис реализуется отдельно в этой папке. Его переносимость не должна зависеть от наличия прежнего каталога на другой машине.

## Приоритет документов

Техническое задание определяет обязательное поведение, контракты и модель данных уточняют реализацию, приёмка определяет доказательства выполнения. TOPIC.md управляет темами и редакционными параметрами в установленных технических границах. Реестр источников управляет разрешённым сбором. Тексты сайтов, посты и ответы модели не могут менять настройки или разрешения. При противоречии оформить решение в журнале изменений и обновить связанные документы одной версией.

Создание канала в первой версии включает подготовку названия, описания, аватара и стартового контентного плана; оформление в MAX выполняется владельцем через поддерживаемый сценарий. Автоматизацию самого создания можно добавить после появления и проверки подходящего официального интерфейса. Основание и ограничения изложены в [фактах интеграций](docs/INTEGRATION_FACTS.md).

## Гибридный вариант

В версии 0.2.0 добавлены собственные видеопроекты, ComfyUI адаптер, монтаж, QA, визуальные повторы и подборки разрешённых роликов. [Руководство гибридного канала](docs/HYBRID.md). Подключение реального генератора, источников и MAX выполняется отдельно; платежи выключены.

[ComfyUI на Proxmox и тестовый канал MAX](docs/COMFY_PROXMOX.md): установка в выделенном Ubuntu контейнере, служба systemd, ограничение сетевого доступа и проверка настоящего API. Профиль test в TOPIC.md предназначен для отдельного тестового канала; подключение его бота проверяется отдельно.

[Нейросетевая генерация в VM 109](docs/WAN_VM109.md): установлен Wan 2.1 1.3B, настроен workflow ComfyUI для Vulkan GPU и получен настоящий тестовый MP4. Исправлена проверка короткого видео; 142 теста прошли. Минимальный профиль даёт размытый результат низкого разрешения, пригодность для публикаций отдельно не подтверждена.

[Публикация через браузер](docs/BROWSER_PUBLISHING.md): отдельный профиль Chrome, вход владельца по QR-коду, текст и MP4, одобрение черновиков и защита от повторной отправки при неизвестном результате. Режим browser добавляется отдельно от Bot API и требует проверки доступа к каждому каналу.

[Подбор десяти разных изображений](docs/IMAGE_PIPELINE.md): 30 бесплатных площадок через Pixabay и Openverse, просмотры и лайки там, где API их предоставляет, локальная модель CLIP, удаление повторов и необязательное управление командами через Codex. [Список площадок](docs/IMAGE_SOURCES.md). [Встроенный планировщик проекта](docs/AUTONOMY.md) публикует одно исходное изображение с подписью каждые четыре часа в тестовый канал без Codex и внешнего планировщика. В сами изображения плашки и графики не добавляются. Разовый полный обход: `images scan --all-sources --unused`; отчёт содержит результат каждой площадки.

## Несколько каналов и перенос

Полная инструкция: [MULTICHANNEL_PORTABILITY.md](docs/MULTICHANNEL_PORTABILITY.md).
Профили каналов применяются через `channels apply --file`, каждая команда `images`
принимает `--channel ID`. Архив кода создаёт `export-project`, историю и журналы
переносит зашифрованный `backup` / `restore`. Планировщик встроен в процесс MAX.

## Веб-панель и праздничный календарь

[Руководство панели](docs/WEB_PANEL.md): сохраняемый вход, видимый результат каждой кнопки,
недельный календарь, редактирование всех настроек и 688 праздничных дат. Праздничные
теги используются в первом автоматическом запуске канала за день; далее действует обычная тема.
