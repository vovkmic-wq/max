# Назначение агента каналов MAX

Проект превращает заданную владельцем тему в регулярно обновляемый канал с полезными, проверяемыми публикациями на русском языке. Агент помогает создать оформление канала, собрать стартовый контекст, вести редакционный календарь, получать новые материалы, устранять повторы и оценивать экономику канала.

## Пользователи и результат

Владелец задаёт тему и границы через TOPIC.md в корне, выбирает пул источников и интервалы, подключает свой канал и определяет допустимую автономность. Редактор проверяет спорные материалы. Оператор отвечает за доступность сервиса и резервные копии. Один человек может выполнять все роли, но система различает их полномочия.

Результат каждого цикла — новые сохранённые материалы, объяснимые решения об отборе, черновики или подтверждённые публикации, ссылки на первоисточники, затраты и журнал ошибок. Повторный запуск после сбоя продолжает работу с сохранённого состояния.

## Первая рабочая версия

- Один активный канал MAX; структура данных и настройки сразу допускают несколько каналов с разными темами и бюджетами.
- OpenCode используется во время работы для анализа, составления плана, перевода, написания и проверки публикаций. Его использование только для написания кода не удовлетворяет требованию «на базе OpenCode».
- Сбор RSS и разрешённых HTML страниц, событий доступных Telegram каналов через Bot API, чтение доступного канала MAX при подтверждённых правах. Коннектор может быть недоступен в конкретной установке, и это явно отображается.
- Текст и изображения с проверенным правом использования. Видео, распознавание аудио и сложные альбомы — расширение после первой версии.
- Очередь, точные и смысловые повторы, русский текст, модерация, расписание, публикация, история, базовые метрики и экспорт.
- Панель владельца на русском языке: источники, черновики, календарь, ошибки, бюджет и отчёты.
- Установка на поддерживаемой машине и перенос базы, медиа и конфигурации с отдельной настройкой секретов.

## Автономность

`dry_run` сохраняет решения и черновики без внешних записей. `review` публикует только одобренную неизменённую ревизию. `autopublish` публикует обычные материалы, прошедшие все проверки. Независимо от режима спорные факты, конфликтующие источники и коммерческие публикации направляются редактору. Автопубликация разрешается по каждому каналу, а не глобально.

Базовый шаблон использует `dry_run`. Это стартовый параметр до заполнения темы и подключения канала; владелец может выбрать более автономный режим после проверки цепочки.

## Расширения

Дополнительные мессенджеры подключаются через контракт источника. Telegram MTProto требует отдельного подключения владельцем и проверки доступа. Автоматическое создание канала, оплату доступа, размещение рекламы, закупку продвижения и работу с внешними площадками вводить отдельными адаптерами с проверкой их возможностей.

## Продвижение и коммерческий результат

Агент готовит полезные рубрики, материалы для собственных площадок, предложения партнёрств, медиакит и планы рекламных экспериментов. Выполнение внешних действий связано с разрешениями на конкретную площадку и бюджетом. Рост подписчиков и доход являются измеряемыми целями продукта; заданные цифры не являются гарантиями.

## Что определяет владелец до запуска

| Решение | Начальное значение | Как влияет |
| --- | --- | --- |
| Тема и границы | Не заданы | Активировать канал нельзя |
| Тип канала и аккаунт MAX | Не заданы | Определяют доступный способ создания и права |
| Источники | Только отключённые примеры | Без реальных источников сбор не начинается |
| LLM провайдер и модель | Не выбраны | Нужна проверка генерации через выбранный OpenCode |
| Публикации | dry_run, до 3 в сутки | После настройки можно изменить |
| Расходы LLM | 0 рублей в сутки | Для платного провайдера требуется положительный лимит |
| Продвижение | Планирование, расходы 0 | Никакие закупки не выполняются |
| Реклама | Выключена | Нужны коммерческие правила и ответственный |

Иллюстративные настройки в комплекте не заменяют эти решения. Конкретная тема не выбрана за владельца.
