# Темы и границы каналов

Этот документ — источник настроек тематики для будущего агента. Для каждого канала владелец задаёт аудиторию, включённые и исключённые подтемы, стиль, расписание и бюджет. Действующая версия определяется полем revision и SHA256 содержимого блока.

## Настройки

Между маркерами TOPIC_CONFIG_BEGIN и TOPIC_CONFIG_END должен находиться ровно один JSON блок. Агент разбирает только его, проверяет по [схеме](schemas/topic.schema.json), затем выполняет смысловую валидацию. Остальная часть документа поясняет заполнение и не расширяет полномочия агента.

## Как заполнить

1. Заменить все строки со словом ЗАПОЛНИТЬ. Тема должна обозначать предмет и пределы, например конкретную отрасль, регион и тип материалов. Пример не является выбранной темой проекта.
2. Включённые темы описывают, какие вопросы полезны читателям. Исключённые темы имеют приоритет при пересечении.
3. Указать аудиторию, языки, географию, сроки актуальности и рубрики. Для вечнозелёного материала редактор может явно отменить ограничение свежести с причиной.
4. Настроить реальный реестр источников по [политике источников](docs/SOURCE_POLICY.md). Связь с каналом осуществляется по id; URL источников в этом документе не дублируются.
5. Задать бюджет и режим. Нулевой бюджет запрещает платные операции; локальная модель допустима после проверки и регистрации нулевой внешней стоимости.
6. Увеличить revision при любом изменении. Включить enabled после заполнения. Привязка id к chat_id MAX хранится в базе через процедуру подключения, а не в тексте темы.

Для нескольких каналов добавить объекты в channels с уникальными id. Материал может быть релевантен нескольким каналам; запрет дублей применяется отдельно к истории каждого канала.

## Правила применения

- Неизвестные поля, повторяющиеся JSON ключи, одинаковые id, неверная зона времени и оставшиеся заглушки в активном канале — ошибки настройки.
- Сервис проверяет ограничения max_chars и допустимость режимов до активации. Уменьшение лимита площадки имеет приоритет над значением этого файла.
- В dry_run отсутствует отправка, правка постов, изменение канала и рекламные расходы. В review требуется одобрение конкретной ревизии. В autopublish работает обязательный контроль качества из ТЗ.
- Изменения сначала проверяются, показывается отличие от активной версии, затем владелец применяет версию. Невалидная правка не уничтожает последнюю действующую конфигурацию.
- Отключение канала и команда pause немедленно блокируют новые отправки; при ошибке разбора попытки отправки приостанавливаются до исправления или явного возврата предыдущей версии.
- Очередные черновики и одобрения при смене версии отправляются на повторную проверку. История уже опубликованных материалов сохраняется.
- TOPIC.md управляет редакционной политикой, но не может разрешить чтение секретов, запуск shell, доступ к произвольным адресам или превышение лимитов системы.
